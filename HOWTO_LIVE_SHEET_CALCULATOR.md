# Как подключить калькулятор к живым данным из Google Таблицы

Пошаговая инструкция для случая: калькулятор должен брать данные из
Google Таблицы, при этом данные должны **обновляться на сайте
автоматически** (без переделки кода) и **не быть видны через F12**
(инструменты разработчика браузера).

Если это правило не читается автоматически (например, работа идёт не
в папке ЭСК) — просто скопируй этот файл целиком в чат.

## Почему это не так просто, как «взять и скопировать данные»

Два требования одновременно:
1. **Живые данные** — значит, браузер должен как-то получать актуальные
   данные при каждом заходе на страницу.
2. **Скрыто от F12** — значит, браузер НЕ может напрямую обращаться к
   Google Таблице (тогда её содержимое будет видно во вкладке Network
   инструментов разработчика).

Из этого следует единственная рабочая схема: **посередине должен быть
сервер**, который сам читает таблицу (ему можно, у него есть служебный
доступ) и отдаёт браузеру только готовый результат — не саму таблицу.
Именно так уже сделано у `climat.html`.

## Общая схема

```
Google Таблица  →  серверная функция (rebar-backend, Vercel)  →  браузер (калькулятор на esk-kz.vercel.app)
   (сырые данные)      (читает через служебный аккаунт,              (получает только готовый JSON,
                        отдаёт JSON)                                  таблицу не видит)
```

## Шаг 1. Подготовить данные в Google Таблице

Таблицы-источники лежат в `D:\Облако ГУГЛ\Claude\Библиотека`
(`AS.gsheet`, `spravochnik-km.gsheet`). Добавь новый лист (вкладку) в
одну из них — новую или существующую, — по фиксированной схеме строк
(уже используется у листа `climat_kz`):

| Строки | Что там |
|---|---|
| 1–4 | Свободные пометки/заголовки для себя — сервер их не читает |
| 5 | **Ключи столбцов** — короткие латинские идентификаторы без пробелов, например `name`, `t_abs_min`, `heat_dur_0` |
| 6 | Человекочитаемые подписи на русском — тоже не читаются сервером, только для тебя |
| 7 и далее | Сами данные, одна строка = одна запись |

## Шаг 2. Настроить доступ к таблице для сервера

Таблицу должна «уметь читать» серверная функция — для этого таблица
расшаривается **конкретно на служебный аккаунт**, а не «всем по
ссылке» (так надёжнее — посторонний человек не откроет её вообще, даже
по прямой ссылке):

1. Открой таблицу → «Настройки доступа» (кнопка «Доступ» справа сверху).
2. Добавь email: `sheets-reader@spravochnik-km.iam.gserviceaccount.com`
3. Права — **Читатель** (Viewer), этого достаточно.
4. Остальным (обычным людям) доступ к этой таблице лучше вообще не
   давать, либо давать только тем, кому реально нужно её редактировать.

## Шаг 3. Добавить ID таблицы в Vercel

1. Скопируй ID таблицы — это часть ссылки:
   `docs.google.com/spreadsheets/d/`**`ЭТОТ_ID`**`/edit`
2. Зайди в Vercel → проект **rebar-backend** (не `эск`!) → **Переменные
   окружения** (Environment Variables).
3. Добавь новую переменную, по образцу уже существующих
   (`GOOGLE_CLIMAT_SHEET_ID`, `GOOGLE_MATERIALS_SHEET_ID`) — например
   `GOOGLE_НАЗВАНИЕ_SHEET_ID` = скопированный ID.
4. Отметь окружение — **Production** (и «Preview», если хочешь
   тестировать до релиза).

## Шаг 4. Написать серверную функцию (это делает Claude)

Нужен доступ к репозиторию `rebar-backend` — если он не склонирован
локально, попроси Claude склонировать его рядом с ЭСК (например, в
`D:\Облако ГУГЛ\Claude\rebar-backend`), либо открыть отдельную сессию
в этой папке.

Функция (например, `api/имя-калькулятора.js`) должна:
1. Прочитать `process.env.GOOGLE_SERVICE_ACCOUNT_JSON` (учётные данные)
   и `process.env.GOOGLE_НАЗВАНИЕ_SHEET_ID` (ID таблицы из шага 3).
2. Через библиотеку `googleapis` авторизоваться и прочитать нужный лист
   (диапазон начиная со строки 5 — строка 5 как заголовки/ключи, данные
   с 7-й строки, как в шаге 1).
3. Собрать из строк массив объектов (ключ — значение из строки 5).
4. Ограничить CORS только доменом сайта (`esk-kz.vercel.app`) — по
   аналогии с уже существующим `contact.js`.
5. Отдать результат как JSON (`res.status(200).json(данные)`).

## Шаг 5. Задеплоить бэкенд

Закоммитить и запушить в репозиторий `rebar-backend` (аналогично тому,
как пушим сам ЭСК — через PowerShell, не Bash). Vercel задеплоит
автоматически.

## Шаг 6. Подключить калькулятор к данным

В самой странице калькулятора (в папке ЭСК) — вместо того чтобы хранить
данные в зашитом в код JS-массиве, страница при загрузке делает:

```js
fetch('https://rebar-backend-henna.vercel.app/api/имя-калькулятора')
  .then(r => r.json())
  .then(data => { /* дальше использовать data как обычно */ });
```

## Шаг 7. Проверить

1. Открыть страницу калькулятора, убедиться, что данные подгрузились
   и расчёт работает.
2. Открыть F12 → Network → найти запрос к
   `rebar-backend-henna.vercel.app/api/...` — убедиться, что в ответе
   только нужные посчитанные поля, а не вся таблица целиком «как есть».
3. Добавить/изменить строку в Google Таблице → перезагрузить страницу
   калькулятора → убедиться, что изменение появилось без правки кода.

## Что можно сделать сразу, а что — потом

Шаги 4–7 (бэкенд и подключение) можно отложить и сделать отдельным
заходом позже — саму страницу калькулятора (расчёт, интерфейс, вёрстку)
можно сначала собрать и проверить на тестовых/зашитых данных, а потом
просто заменить источник данных на `fetch` из шага 6, ничего в логике
расчёта не трогая.
