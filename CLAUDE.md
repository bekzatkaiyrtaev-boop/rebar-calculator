# ЭСК — Электронный справочник конструктора

Статический сайт-справочник для инженеров-строителей: набор HTML-калькуляторов
(сортаменты металлопроката, ЖБК, кладка, теплотехника и т.д.) на чистом
HTML/CSS/JS без сборки и фреймворков. Каждая страница — самостоятельный файл.

Этот файл читается автоматически в начале каждой сессии в этой папке —
не нужно объяснять конвенции ниже заново в новом чате.

## 1. Обязательные общие подключения

Каждая страница справочника (кроме сугубо служебных) подключает общую
шапку/футер и (для калькуляторов) структуру сайта:

```html
<link rel="stylesheet" href="site-header.css">
<link rel="stylesheet" href="site-footer.css">
...
<div id="site-header"></div>
...
<div id="site-footer"></div>

<script src="site-structure.js"></script>
<script src="site-header.js"></script>
<script src="site-footer.js"></script>
```

Важно:
- `site-structure.js` подключается **до** `site-header.js` (иначе не
  заработают кнопки «Назад/Вперёд» — они строятся из общего списка
  страниц).
- Шапка и футер — общие файлы, их стили/логику в самой странице не
  дублировать и не переопределять.
- Гейт доступа через Google-вход (в `site-header.js`) закрывает все
  страницы, кроме `index.html` и `about.html`, автоматически — на
  новой странице ничего специально включать не нужно.

## 2. Ширина страницы

**Единый стандарт — `max-width: 1100px`**, на обёртке всего контента
(класс называется по-разному: `.page-wrap`, `.page`, `.wrap`, `.layout` —
смотри по аналогии с соседними файлами). Это совпадает с шириной шапки
сайта (`site-header.css`), поэтому шапка и контент всегда одной ширины.

Исключение: `vedomost-peremychek.html` — 1380px, там реально широкая
таблица. Новую страницу с исключительно широкой таблицей можно расширить
аналогично, но по умолчанию — 1100px.

## 3. Цветовая палитра и шрифты (для новых страниц)

Большинство страниц (все страницы металлопроката, климат, конвертер и
т.д.) используют один и тот же набор CSS-переменных — **бери его за
основу для новых калькуляторов**:

```css
:root {
  --bg:       #0f1117;
  --surface:  #1a1d27;
  --surface2: #22263a;
  --border:   #2e3347;
  --accent:   #4f8ef7;
  --green:    #7dd3a8;
  --warn:     #f4b942;
  --red:      #ef4444;
  --text:     #d6daf0;
  --muted:    #6b7099;
  --mono:     'JetBrains Mono','Courier New',monospace;
  --sans:     'Inter','Segoe UI',sans-serif;
}
body{background:var(--bg);color:var(--text);font-family:var(--sans);font-size:14px;line-height:1.55;}
```

Самый быстрый способ начать новую страницу — скопировать целиком
`<style>`-блок из похожей по смыслу существующей страницы (например,
`trubi.html` или `shvellery.html`) — там уже есть готовые классы
`.card`, `.card-header`, `.field-grid`, `.design-grid`/`.design-cell`,
`table.datatable` и т.д., которые переиспользуются почти везде.

**Известная непоследовательность (не обязательно чинить, просто знать):**
у части старых страниц — `armatura-34028-2016.html`, `kirpich-530-2012.html`,
`silikat-379-2015.html`, `podbor-secheniya-armatury.html`,
`Vedomost_elementov.html`, `prodavlivanie-fundament.html` — своя, чуть
другая палитра переменных (`--text-primary`, `--bg-elevated` и т.п.).
Для НОВЫХ страниц ориентируйся на палитру выше, эту группу трогать не
обязательно.

## 4. Числовые поля

Стрелочки ▲▼ у `<input type="number">` убраны глобально через
`site-header.css` (правило `-webkit-appearance: none` и т.д.). На новой
странице ничего для этого добавлять не нужно — просто используй обычный
`<input type="number">`.

## 4.1. CSS Grid/Flex — «раздутие» колонок с `<select>`/полями

Частый баг: строка из нескольких `<select>`/полей в `display:grid`
(или `display:flex`) вылезает за карточку/`.page-wrap` вбок. Причина —
у элементов сетки по умолчанию `min-width:auto`, из-за чего колонка не
может сжаться меньше содержимого (текста в `<select>`) даже если сама
дорожка сетки (`1fr` и т.п.) уже. Фикс — добавить `min-width:0` на сам
элемент-ячейку (`.field` и т.п.), не на сетку:

```css
.field { display:flex; flex-direction:column; gap:6px; min-width:0; }
```

Проверять на страницах, где в одной строке несколько select/инпутов
разной ширины (частый паттерн: «Тип» + «Категория» + узкое поле сбоку).

## 5. Чек-лист для нового калькулятора

1. Взять за основу похожую существующую страницу (проще всего
   скопировать файл целиком и переписать содержимое).
2. Проверить: подключены `site-header.css`/`site-footer.css`,
   `#site-header`/`#site-footer`, три скрипта в правильном порядке
   (см. п.1).
3. Ширина обёртки — 1100px (см. п.2).
4. Зарегистрировать страницу в [site-structure.js](site-structure.js) —
   добавить объект `{ title, desc, ref, href }` в нужный раздел/подраздел
   `SECTIONS`. Без этого страница не появится в оглавлении и не попадёт
   в кнопки «Назад/Вперёд».
5. Добавить сохранение введённых данных в `localStorage` (см. п.11) —
   для новых калькуляторов это стандарт, не опция.
6. Проверить в браузере (через превью-сервер), что нет ошибок в консоли
   и калькулятор считает.

## 7. Калькуляторы с данными из Google Таблиц — НЕ копировать данные в HTML

Если пользователь говорит, что данные калькулятора должны браться из
Google Таблицы (в `D:\Облако ГУГЛ\Claude\Библиотека`) — **не копируй
данные из таблицы прямо в HTML/JS-массив**. Так делать нельзя: это
работает один раз, но при добавлении новых строк в таблицу они не
попадут на сайт (в HTML — застывший снимок на момент копирования).

Правильный путь — тот же, что уже используется у `climat.html`:
1. Серверная функция в отдельном репозитории `rebar-backend` (не
   склонирован локально по умолчанию — см. `project-esk-infra` в
   памяти, либо спросить пользователя) читает Google Таблицу на сервере
   через сервисный аккаунт и переменную окружения `GOOGLE_*_SHEET_ID`
   в Vercel.
2. Страница калькулятора запрашивает данные у этой функции (`fetch`),
   а не хранит их в себе.

Так данные остаются живыми (обновление таблицы сразу видно на сайте) и
защищёнными (сырое содержимое таблицы не видно через F12 — см. п.
про Библиотеку в памяти). **Прямой fetch из браузера в публичный
CSV/JSON-экспорт Google Таблицы (`gviz/tq` и т.п.) не подходит** — это
и «не защищено» одновременно, требует открыть таблицу по ссылке всем.

Если непонятно, нужен ли конкретному калькулятору именно такой (живой)
источник данных, или достаточно обычного зашитого в HTML массива (как у
большинства существующих страниц) — **спроси пользователя**, не
угадывай молча.

**Подробная пошаговая инструкция, как это настроить** —
[HOWTO_LIVE_SHEET_CALCULATOR.md](HOWTO_LIVE_SHEET_CALCULATOR.md).

## 8. Бейджи-ссылки на нормативы (`.ref`)

В шапке карточки (`.card-header`) рядом с заголовком часто стоит
маленькая подпись на норматив — `<span class="ref">СП РК ...</span>`.
Она должна быть **лёгкой, без рамки и фона** — просто приглушённый
цветной текст, чтобы не создавать «коробочный» вид рядом с заголовком:

```css
.card-header .ref{font-family:var(--mono);font-size:10.5px;color:var(--accent);background:transparent;border:none;padding:0;opacity:.85;}
```

На части старых страниц (`climat.html`, `trubi.html`, `pv-listy.html`,
`peregorodka.html`, `podbor-uteplitelya.html`) раньше был вариант с
рамкой и фоном (`background:var(--bg);border:1px solid var(--border);
padding:3px 8px;border-radius:4px;`) — это исправлено, для новых
страниц использовать только облегчённый вариант выше.

## 9. Карточка «Условное обозначение при заказе» — привязка к выбору пользователя

Если на странице есть подбор профиля/листа/плиты (селекты типоразмера,
толщины, диаметра и т.п.) и рядом карточка «Условное обозначение при
заказе» — **обозначение должно строиться из реально выбранных
пользователем данных**, а не быть статичным текстом-примером. Иначе
после подбора профиля 300×100×6 пользователь видит в примере совсем
другой типоразмер — сбивает с толку.

Как сделать:
1. В HTML заменить захардкоженные числа в примере на `<span id="...">`
   (например `markingDims`, `markingT`, `desigNomer`) — сам текст-код
   обозначения тоже через `id`, чтобы обновлять `textContent`.
2. В JS — в той же функции `render()`/`onSizeChange()`, которая уже
   перерисовывает результаты подбора, добавить обновление этих полей
   на основе текущих `entry`/`row`/`currentShape` и т.п. (переменные
   там уже есть, доп. запросов к данным не нужно).
3. Если на странице есть переключатель режимов (квадрат/прямоугольник,
   балка/швеллер, ромб/чечевица) — обозначение должно учитывать и его
   (следить за тем, какой режим активен сейчас).
4. Что можно оставить статичным: атрибуты, которые пользователь в
   принципе не выбирает на этой странице (класс прочности, длина,
   категория коррозионной стойкости и т.п.) — их можно зашить как
   правдоподобный дефолт (см. пример ниже), просто не выдавать их за
   часть подбора.

Пример (`trubi.html`, `render()`):
```js
document.getElementById('markingDims').textContent = dims;
document.getElementById('markingT').textContent = t;
document.getElementById('markingMerny').textContent = `${prefix}-${dims}×${t}×6000-КП245-ГОСТ 30245-2012`;
```

Уже сделано (пример для копирования): `trubi.html`, `trubi-8732.html`,
`trubi-10704.html`, `dvutavry-gost.html`, `shvellery.html`, `ugolki.html`,
`pv-listy.html`, `rifl-listy.html`, `special-beams-19425.html`.

## 10. Пошаговые расчёты с формулами — KaTeX

Для калькуляторов с развёрнутым «Промежуточные шаги» / отчётом, где
формулы должны выглядеть как в учебнике (дроби, индексы, греческие буквы),
а не одной строкой текста — использовать **KaTeX**, а не собирать формулы
вручную из HTML/юникода. Пример: `peremychka-ugolok.html`.

Подключение (в `<head>`, после общего `<style>`):
```html
<link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/KaTeX/0.16.9/katex.min.css">
<script src="https://cdnjs.cloudflare.com/ajax/libs/KaTeX/0.16.9/katex.min.js"></script>
<script src="https://cdnjs.cloudflare.com/ajax/libs/KaTeX/0.16.9/contrib/auto-render.min.js"></script>
```

Рендер — одна общая функция, вызывается на контейнере после того, как в
него вставлен HTML со строками формул:
```js
function renderMath(el){
  if(window.renderMathInElement){
    renderMathInElement(el, {
      delimiters: [
        {left: "$$", right: "$$", display: true},
        {left: "$", right: "$", display: false}
      ],
      throwOnError: false
    });
  }
}
// после output.innerHTML = html;
renderMath(output);
```

Сами формулы — обычные LaTeX-строки в шаблонных литералах JS, между `$$...$$`:
```js
`$$M_{Ed} = \\frac{G_d\\cdot L_{расч}}{6} = \\frac{${Wd.toFixed(3)}\\times ${Lcalc.toFixed(3)}}{6} = ${M_Ed.toFixed(3)}\\text{ кН·м}$$`
```
Кириллица внутри `\text{...}` работает (даёт неопасный warning в консоли
`unicodeTextInMathMode`, не ошибку) — так и подписываются русские
переменные/единицы измерения.

**Известная ловушка:** символ «·» (точка умножения) **нельзя** ставить
внутри `\text{...}` — KaTeX внутренне подменяет его на макрос `\cdotp`,
который не разворачивается в текстовом режиме, и на странице печатается
буквально `\cdotp` вместо точки. Если между двумя текстовыми частями
(например, единицами кН и м) нужна точка — выносить её в математический
режим отдельно:
```js
// неправильно:            \\text{ кН·м}
// правильно:               \\text{ кН}{\\cdot}\\text{м}
```

Если на странице есть кнопка печати (`window.print()` в `#printArea`) —
`renderMath()` нужно вызвать второй раз на `#printArea` после того, как
туда скопирован `lastReportHTML`, иначе в напечатанной версии формулы
останутся необработанным LaTeX-текстом.

## 11. Сохранение введённых данных между визитами (localStorage)

**Для НОВЫХ калькуляторов** — исходные данные должны сохраняться в
`localStorage` и восстанавливаться при повторном заходе на страницу
(в т.ч. после перехода на другую страницу ЭСК и возврата кнопкой
«Назад» сайта или браузера). Пример реализации — `peremychka-2ugolka.html`.

**Существующие калькуляторы массово не переделывать** — у каждого свой
набор id полей и свой порядок инициализации (какие select'ы заполняются
динамически, какие блоки показываются/скрываются условно), поэтому это
не копипаст, а отдельная проверка на каждый файл. Обновлять по мере
того, как до конкретного калькулятора доходит очередь по другим
задачам, а не отдельным проходом по всем сразу.

Шаблон (адаптировать под реальные id полей страницы):

```js
document.getElementById('inputsCard').addEventListener('input', calc);
document.getElementById('inputsCard').addEventListener('change', calc);

// === Сохранение введённых данных между визитами (localStorage) ===
const FORM_STORAGE_KEY = 'esk-<имя-файла-без-расширения>-v1'; // уникальный на страницу
const FORM_FIELD_IDS = ['Lpr','twall','steel', /* ...все id полей ввода на странице */];
function saveFormState(){
  try{
    const state = {};
    FORM_FIELD_IDS.forEach(id=>{
      const el = document.getElementById(id);
      if(!el) return;
      state[id] = (el.type === 'checkbox') ? el.checked : el.value;
    });
    localStorage.setItem(FORM_STORAGE_KEY, JSON.stringify(state));
  }catch(e){}
}
function loadFormState(){
  try{
    const raw = localStorage.getItem(FORM_STORAGE_KEY);
    if(!raw) return;
    const state = JSON.parse(raw);
    FORM_FIELD_IDS.forEach(id=>{
      if(!(id in state)) return;
      const el = document.getElementById(id);
      if(!el) return;
      if(el.type === 'checkbox') el.checked = state[id];
      else el.value = state[id];
      el.dispatchEvent(new Event('change', {bubbles:true})); // подтягивает зависимую видимость блоков
    });
  }catch(e){}
}
document.getElementById('inputsCard').addEventListener('input', saveFormState);
document.getElementById('inputsCard').addEventListener('change', saveFormState);
```

Важно:
- `FORM_STORAGE_KEY` — обязательно с именем файла в ключе, иначе разные
  калькуляторы будут затирать данные друг друга (используется общий
  `localStorage` на весь домен сайта).
- `FORM_FIELD_IDS` — перечислить **все** id полей ввода страницы
  (`input`, `select`, чекбоксы), включая те, что скрыты условно (это
  безопасно, `getElementById` на несуществующий/скрытый элемент просто
  вернёт его текущее значение).
- Если на странице есть select с **динамически генерируемыми
  опциями** (сортамент, зависящий от другого select — как
  `ownAngleSelect`, зависящий от `angleType`) — в `FORM_FIELD_IDS` он
  должен идти **после** того select'а, от которого зависит его список
  опций, иначе восстановленное значение будет сброшено при
  перегенерации списка.
- Вызов `loadFormState()` — в самом конце скрипта, после того как все
  функции инициализации (заполнение динамических select'ов и т.п.) уже
  отработали, непосредственно перед первым `calc()`:
  ```js
  loadFormState();
  calc();
  ```

## 12. Иллюстративные схемы/картинки в калькуляторе — не рисовать самому без согласия

Если для калькулятора нужна схема/иллюстрация (например, расчётная схема
перемычки с размерами) и пользователь уже прислал референс-картинку —
**не рисовать её самостоятельно с нуля (SVG и т.п.) без вопроса**. Даже
технически корректный самодельный рисунок может выглядеть топорно рядом
с тем, что на самом деле нужно пользователю.

Правильный порядок:
1. Спросить — использовать присланную пользователем картинку как есть,
   или нарисовать схему самому (SVG под цветовую палитру сайта, п.3).
2. Если пользователь хочет свою картинку — **инструменты агента не могут
   сами вытащить картинку, вставленную в чат, и сохранить её на диск**
   (нет такого инструмента). Нужно попросить пользователя сохранить файл
   в папку проекта и назвать путь/имя файла, и уже потом подключать его
   через `<img src="...">`.
3. Если рисовать самому — держаться палитры из п.3 (переменные
   `var(--text)`/`var(--muted)`/`var(--accent)` и т.п. работают прямо в
   SVG-атрибутах `stroke`/`fill`, уже используется на сайте, например в
   `pustotki.html`), и не оборачивать картинку в отдельную рамку/карточку
   с фоном — она должна сливаться с карточкой `.card`, в которой стоит.

## 13. Компактная табличная форма для карточек с полями ввода

Если в карточке много полей и стандартный вариант (каждое поле — отдельный
`.field` с подписью сверху и отступами вокруг) выглядит раздробленным —
переоформить в единую таблицу «подпись слева / значение справа», одно поле
на строку, без разбивки на 2 колонки. Пример: `podbor-uteplitelya.html`,
карточка «Исходные данные».

```html
<table class="input-table">
  <tr>
    <td class="it-label">Наименование объекта</td>
    <td class="it-value"><input type="text" id="objName"></td>
  </tr>
  ...
</table>
```
```css
table.input-table{width:100%;border-collapse:collapse;font-size:13px;}
table.input-table td{padding:6px 16px;border-bottom:1px solid var(--border);vertical-align:middle;}
table.input-table tr:last-child td{border-bottom:none;}
table.input-table td.it-label{width:260px;color:var(--muted);font-size:11px;font-weight:600;text-transform:uppercase;letter-spacing:.6px;}
table.input-table td.it-value{position:relative;}
```

Карточка при этом должна получить `<div class="card-body" style="padding:0;">`
(без внутреннего отступа) — иначе таблица окажется в «рамке внутри рамки»,
как отдельная плашка внутри карточки, а не вплотную к её краям (тот же
принцип, что и у `.result-grid`/`table.usedparams` — см. их разметку).

Если полей мало и они логически парные (2 в ряд) — компактную таблицу
можно не делать, обычных `.field-row` достаточно; переходить на таблицу
имеет смысл, когда полей от 5-6 и больше на одну карточку.

## 14. Цвет значения поля — что вводит пользователь, а что нет

Чтобы пользователь с одного взгляда понимал, какие поля нужно заполнить
самому, а какие — блокированы/вычисляются автоматически, цвет **текста
значения** (не подписи — подпись всегда `var(--muted)`, приглушённая
uppercase) несёт смысл:

- **`var(--green)`** — поле редактируется пользователем прямо сейчас
  (текст/число/выбранный option в select, плейсхолдер — тем же зелёным
  с `opacity:.65`).
- **обычный `var(--text)` + `opacity`/`readonly`-стиль** — поле
  заблокировано (например λ материала, пока не включён режим автора).
- **`var(--accent)`** — значение показано только для информации,
  вычислено автоматически и в принципе не редактируется на этой странице
  (курсивный пример — климатические параметры города).

```css
.field input[type=text],.field input[type=number],.field select{color:var(--green);}
.field input::placeholder{color:var(--green);opacity:.65;}
table.layers input[type=text]:not([readonly]),
table.layers input[type=number]:not([readonly]){color:var(--green);}
```

Правило простое: **если элемент можно менять руками прямо на этой
странице — его значение зелёное**; всё остальное — нет. Применять новым
и существующим калькуляторам по мере правок, отдельным проходом по всем
сразу — не нужно (как и с localStorage в п.11).

## 15. Лёгкие поля ввода — рамка/фон только на hover/focus

Вместо постоянно видимой «коробки» у `<input>`/`<select>` (фон
`var(--surface2)` + рамка `var(--border)` всегда) — рамка и фон
показываются только при наведении или фокусе, в состоянии покоя поле
выглядит как обычный текст. Особенно важно, когда на одной карточке
много полей подряд («слишком много полей не дают сосредоточиться на
данных» — реальная формулировка фидбека, из-за которой это и появилось).

```css
.field input[type=text],.field input[type=number],.field select{
  background:transparent;border:1px solid transparent;
  transition:background .15s,border-color .15s;
}
.field input:hover,.field select:hover{background:var(--surface2);border-color:var(--border);}
.field input:focus,.field select:focus{background:var(--surface2);border-color:var(--accent);}
```

**Ловушка с фокусом на кнопках-иконках:** если у `.icon-btn` (например
кнопки ↑+/↓+/× в таблице слоёв) фон/рамка тоже прозрачные в покое —
браузерная рамка фокуса по умолчанию (синяя) начинает бросаться в глаза
сильнее, чем раньше (на закрашенной кнопке она была незаметна). Сразу
добавлять `:focus-visible` с той же подсветкой, что и `:hover`, вместо
дефолтного `outline`:
```css
.icon-btn:hover,.icon-btn:focus-visible{background:var(--surface2);color:var(--accent);outline:none;}
```

## 16. Сворачиваемые второстепенные блоки — `<details>`, свёрнуты по умолчанию

Если на странице несколько карточек с «техническими» данными, которые
нужны не всегда (промежуточные формулы, использованные для проверки
данные, вспомогательные графики) — оборачивать в `<details>` без атрибута
`open`, чтобы при заходе на страницу они были свёрнуты и не удлиняли
страницу. Сам `.card-header` становится `<summary>`:

```html
<div class="card">
  <details>
    <summary class="card-header">
      <span class="title"><span class="details-arrow">▶</span>Название блока</span>
      <span class="ref">норматив</span>
    </summary>
    <div class="card-body">...</div>
  </details>
</div>
```
```css
summary.card-header{cursor:pointer;list-style:none;user-select:none;}
summary.card-header::-webkit-details-marker{display:none;}
.details-arrow{display:inline-block;margin-right:8px;font-size:10px;color:var(--accent);transition:transform .15s ease;}
details[open] > summary.card-header .details-arrow{transform:rotate(90deg);}
```

Что оставлять развёрнутым (не оборачивать в `details`): исходные данные,
итоговый результат/вывод — то, что пользователь смотрит в первую очередь
при каждом заходе.

## 17. Печатный отчёт — таблицы с «зеброй» и подсветкой значимой строки

Дополнение к п.10 (KaTeX-отчёт через `#printArea`): таблицы отчёта
(`.summary-table`) не должны быть монотонной простынёй — чередование
фона строк помогает читать длинные таблицы (например состав конструкции
с длинными названиями материалов), а значимую строку (например слой
утеплителя) стоит подсветить отдельно:

```css
.summary-table tr:nth-child(even) td{background:#f5f6f8;}
```
```js
// подсветка конкретной строки — инлайн-стиль на <td>, а не на <tr>:
// фон, заданный на самой ячейке, всегда перекрывает фон строки от nth-child,
// независимо от порядка и специфичности правил
const bg = l.isInsulation ? 'background:#fbe4e1;' : '';
`<tr><td style="${bg}">...</td></tr>`
```

Также у таблицы состава конструкции указывать `table-layout:fixed` с
фиксированной шириной для узких колонок (№, λ, толщина) и без ширины —
для «Материала»: так колонка с названием гарантированно забирает всё
оставшееся место вместо непредсказуемого авто-распределения браузера.

## 18. Тултипы/поповеры внутри карточек — `position:fixed`, не `absolute`

У всех `.card` стоит `overflow:hidden` (чтобы скруглённые углы обрезали
контент). Если тултип/поповер внутри карточки использует
`position:absolute` относительно родителя — при открытии рядом с нижним
краем карточки он окажется почти полностью обрезан и «не будет
всплывать» (визуально ничего не произойдёт при клике). Симптом трудно
диагностировать по скриншоту — `display` реально переключается в
`block`, элемент просто невидим из-за обрезки родителем.

Фикс — как и у выпадающих списков (`combo-dropdown`, см.
`positionDropdownFixed()` в `trubi.html`/`podbor-uteplitelya.html`):
считать координаты кнопки-триггера через `getBoundingClientRect()` и
позиционировать тултип через `position:fixed` с явными `left`/`top`,
устанавливаемыми в JS при открытии — тогда `overflow:hidden` родителя
не действует:

```js
function toggleTooltip(e){
  e.stopPropagation();
  const box = document.getElementById('myTooltip');
  const show = box.style.display !== 'block';
  if (show){
    const r = e.currentTarget.getBoundingClientRect();
    box.style.left = Math.max(8, r.left) + 'px';
    box.style.top = (r.bottom + 6) + 'px';
    box.style.display = 'block';
  } else box.style.display = 'none';
}
```
```css
.tooltip-box{position:fixed; /* не absolute */ ...}
```

## 19. Своя стрелочка у кастомных комбобоксов — SVG, не юникод-символ

Если поле визуально должно выглядеть как `<select>`, но на деле это
`<input>` с выпадающим списком (комбобокс с поиском, например выбор
города) — стрелочку-индикатор делать через инлайн SVG-шеврон
(`stroke="currentColor"`), а не юникод-символ вроде `▾`. Символ в мелком
кегле в разных шрифтах рендерится нечётко (маленькой кляксой), заметно
хуже чёткой стрелки, которую рисует браузер у нативного `<select>` —
из-за этого поля на одной странице визуально «не совпадают».

```html
<button type="button" class="combo-arrow">
  <svg width="10" height="6" viewBox="0 0 10 6" fill="none" xmlns="http://www.w3.org/2000/svg">
    <path d="M1 1L5 5L9 1" stroke="currentColor" stroke-width="1.4" stroke-linecap="round" stroke-linejoin="round"/>
  </svg>
</button>
```
`stroke="currentColor"` — цвет наследуется от `color` кнопки, поэтому
достаточно один раз задать `.combo-arrow{color:var(--green);}` (см. п.14)
и он совпадёт с цветом стрелочек у соседних `<select>`.

## 20. Автоподстановка поля из уже выбранного справочного значения

Если значение поля можно надёжно вывести из другого уже выбранного
справочного поля (например «зона влажности района строительства» — из
выбранного города, если в таблице климатики есть такая колонка) —
предпочитать автоподстановку отдельному ручному полю, которое
пользователь может забыть переключить правильно. Показывать
подставленное значение рядом с полем-источником (короткой подсказкой в
скобках), а не отдельной всегда открытой карточкой — если это
второстепенная информация, а не то, что пользователь читает в первую
очередь.

При чтении поля из Google Таблицы (см. п.7) — проверять несколько
вероятных вариантов ключа столбца, а не один жёстко заданный: реальные
заголовки в таблице люди могут переименовать, ключ и подпись — перепутать
местами при заполнении:
```js
const raw = city['humidity_zone'] || city['зона_влажности'] || city['dry/normal/wet'];
```
