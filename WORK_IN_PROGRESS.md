## SEO PSD PRO — большой заход 28.09 (ЗАКОММИЧЕНО 286c9b9, ВЫЛОЖЕНО, ПРОВЕРЕНО НА ПРОДЕ)
Цель — вывести psdpro.kz в топ. Аудит показал: сайт не находился **ни по одному** профильному запросу. Причины и что сделано:

**1. Гейт входа стоял на всю страницу калькулятора.** Посетитель из поиска упирался в замок → уходил → Google понижал страницу. Переведено на **фримиум по действию**: расчёт открыт всем, вход нужен только чтобы распечатать/сохранить. Сделано одной правкой в `site-header.js` — перехват `window.print()`, новые калькуляторы получат гейт автоматически. Есть `window.PSDPRO.requireAuth(reason, action)` для других платных действий. Убран мёртвый `FREE_ACCESS_PAGES`/`openAccess`.
  - Проверкой вскрылась дыра: страницы заполняют `#printArea` ДО вызова `print()`, и после отказа от входа записка оставалась в DOM — уезжала на принтер по Ctrl+P мимо гейта. Теперь при отказе `#printArea` очищается.

**2. Перемычки и ветер были невидимы для поиска вообще.** Обе страницы — оболочки с `<iframe>` на `_embed-*.html`, а те закрыты `Disallow: /_embed-`. Google видел заголовок, вкладки и пустоту. Разделено на настоящие страницы:
  - `peremychka.html` → хаб (сравнение трёх способов) + `peremychka-ugolok.html`, `peremychka-2ugolka.html`, `peremychki-1038.html`
  - `veter-nagruzka.html` → хаб + `veter-steny.html`, `veter-krovlya.html` (у этих двух вдобавок не было видимого `<h1>` — единственный сидел в шаблоне печати, исправлено)
  - Вкладки остались визуально теми же, но это настоящие `<a href>`.
  - **Важно про `pushState`:** пользователь предлагал оставить один файл и менять URL через `history.pushState()` — не работает. Google запрашивает URL у сервера, на статике это 404. Нужны реальные файлы.

**3. Текстовые блоки `<details>` внизу калькуляторов** (идея пользователя: свёрнуто, читателя не отвлекает, роботом индексируется).
